## 2. D19 — unchanged, now confirmed verbatim from the live file (matches this repo's prior record)
```
D19_oracle_domain_clamp (v1.9, user 2026-10-15):
Every method must decide adversariality on the exact clamped [0, 1] pixel image that is stored and scored. Two
oracle-domain defects were identified and fixed:
  (1) ARS_OPT: tracker victim wrapped in ClampedVictim (pixel-space scalar clamp to [0, 1]); recorded in
      env_ARS_OPT.json and run_manifest.json as oracle_domain = "clamp01".
  (2) CGBA / CGBA_H: bin_search (:77-85) and SemiCircular_boundary_search (:179-191, incl. the patched fixed
      copy) do not clip queries, while hardlabel_tracker.py decided on the unclamped normalised query and
      stored the clamped pixel projection separately. Fix: wrap the raw net in make_tracker with
      ClampedVictimNormalized using per-channel bounds lb = normalize(0), ub = normalize(1) (never the scalar
      ClampedVictim), so every normalised-space query is clamped before the decision; recorded in
      env_CGBA*.json and run_manifest.json as oracle_domain = "clamp_normalized".
Both fixes alter what the search itself queries whenever a probe leaves range, requiring a full re-run of all
affected ARS_OPT and CGBA / CGBA_H cells.
```
This matches, word for word in substance, what `../handoffs-and-reviews/2026-10-15_b4h_t1b_verified_and_cgba_fix_spec.md`
and `2026-10-15_b4h_t3_verification.md` already documented. No correction needed here — this entry is solid.

## 4. D5 / E10 / E11 / E12 — scope narrowed to ImageNet + one robust model; no conditional sections remain
```
D5_conditional_sections (v1.9-rev3, user 2026-10-16):
No conditional sections remain. E8 is a DERIVED view of E1-E7 (no additional runs; all 8 checkpoints recorded
per D1). E12 CUT (data available in E11's budget-1000 rows). E10 (Places365) CUT (ImageNet-only scope).
E11 (RobustBench R50) REQUIRED.
```
- **E10 (Places365 cross-dataset generalization): CUT.** The paper's scope is now ImageNet-only for the main study,
  plus the one robust-model element (E11). This is a bigger scope change than it might look: every B4b/B4c/B4e/B4e-followup
  document in `../handoffs-and-reviews/` that spends significant effort on Places365 smoke, split registration,
  and cost tables (B4b's 29.01 GPU-h E10 estimate, the resnet50_places365/densenet161_places365 victim setup) is
  now evidence for **work that will not appear in the final paper's main tables** — it stays valid project history
  (and arguably strengthens confidence in the pipeline, since it was tested on more victims than ended up needed),
  but a new team member should not expect an E10 Places365 table in the eventual manuscript.
- **E11 (RobustBench Salman2020Do_R50): REQUIRED, unchanged.** Still 2 modes, n=200, methods {LGC_RC_EGC, TtBA,
  CGBA, CGBA_H} (ARS_OPT's addition to E11, discussed as a live decision in `../b5-planning/2026-10-15_b5_signoff_plan.md`
  §5-§6, is **not** reflected in this E11 methods list — check the live contract again before assuming ARS_OPT is
  in E11 for the actual B5 run).
- **E12 was *redefined*, not just re-justified.** It is no longer "extra victims to be named" (the old CONDITIONAL
  text this repo's prior extract still showed) — it is now explicitly "low-query extension on robust R50 (budget
  1000, n=200, non_targeted)," and *that* new definition is CUT because E11 already records all 8 checkpoints
  (including budget 1000) under D1. Note for anyone who read `../b5-planning/2026-10-15_b5_signoff_plan.md` §1 item 3:
  that doc flagged "E12 rationale 'data already in E11's budget-1000 rows' is wrong" — that criticism applied to
  the *old* E12 definition (extra victims) and no longer applies now that E12 itself was redefined to be exactly
  the thing E11 already covers. This is not the same error recurring; it is a legitimate resolution via redefinition.
